What is a hard fork? How Cardano upgrades without splitting the chain | Crypto from Zero #9

Oct 27 · explainer

Watch on YouTube · the figures on screen (JSON) · every claim and how it resolved

Transcript

Cold open

A hard fork sounds like a split, and on some chains it has been one. On Cardano it is a scheduled upgrade, voted on-chain. Here is the difference, and what governance has decided recently.

Changing the rules

Every node follows the same rules for what counts as a valid block. A soft fork tightens those rules, so old nodes still accept the new blocks. A hard fork changes them in a way old nodes reject, so everyone must upgrade. If some refuse, the chain can split in two, which is how Bitcoin Cash and Ethereum Classic began.

A new rulebook

Think of a board game whose rulebook changes. A soft fork is like banning a move: players with the old rulebook can keep playing, because every game under the new rules is still legal under the old ones. A hard fork adds a new kind of move. Players with the old rulebook see it as cheating, so everyone has to update, or end up playing a different game.

How Cardano does it

Cardano runs hard forks as scheduled upgrades. Node software that knows the new rules ships first; the switch happens only at an epoch boundary, once a hard fork governance action is ratified by DReps, stake pools and the constitutional committee. Its most recent one, in July 2026, moved the chain to protocol version eleven.

An upgrade, step by step

Here is what that looks like in practice. Weeks ahead, pool operators install node software that understands both the old and the new rules. Nothing changes yet. A governance action proposes the switch, and the committee, stake pools and DReps vote. Once it is ratified, every node moves to the new rules together, at the same epoch boundary. There is no race and no split, because everyone is ready before the switch.

Changing without splitting

Every chain has to change eventually, to add features or fix problems. How it changes decides who has a say, and whether its community stays together. Cardano puts each upgrade to an on-chain vote and gives everyone time to prepare, which is how it has upgraded many times without splitting.

What passed

That is how it works on paper. Here is what the chain recorded. Over the last ninety days 7 actions reached an outcome: 1 enacted, 6 expired without passing; the table shows the latest 6 of them. Each row gives DRep votes for, against and abstaining, by count and by voting power, and the yes share of the power that voted yes or no, with abstains left out of it. A high yes share can still expire: to pass, the yes vote has to reach a set share of all active DRep voting power, abstentions aside, so a DRep that does not vote counts against it, and where stake pools or the committee also vote, each has its own threshold to clear. The last column gives the stake pools' yes share by stake, then the committee's votes for and against, where either body voted. One of the expired was an info action, which records a vote but can never be enacted.

The short version

So, in short. A hard fork changes the rules every node must follow; Cardano schedules them through a governance vote and switches at an epoch boundary.
